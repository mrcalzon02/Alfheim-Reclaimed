# Alfheim Golems — continuous goal ledger

This ledger is the durable control surface for goal-oriented development. Update it when evidence is
created, not from memory at the end of a session. Detailed contracts and gates live in
`ALFHEIM_GOLEMS_PLAN.md`.

## Status vocabulary

`proposed`, `ready`, `active`, `static validated`, `automated runtime validated`, `automated
client/fresh-world validated`, `production admitted`, `deferred`, `rejected`, `blocked`.

An evidence cell names the exact test, world/run identifier, output path or artifact hash. “Tested”
is not evidence. A goal never advances because a later goal happens to work.

No evidence row may say “owner playtest,” “manual review” or equivalent. All required evidence is
generated by automated tests, scripted servers/surveys or automated client interaction and capture.

## Session close checklist

- Update the active slice and stage row with the highest acceptance state actually evidenced.
- Record newly discovered defects under the same goal; do not hide them in a later stage.
- Put intent changes in B-92, live evidence in `EXECUTION_STATE.md`, and completed shipped changes in
  `CHANGELOG.md`.
- Record artifact hashes when a jar is copied to client/server and prove the copies match.
- Name every deferred runtime/client gate and its resumption condition.
- Never hand a runtime or visual-validation step to the owner; automate it or make it non-blocking.
- Leave one next exact action small enough to begin without rediscovering context.
